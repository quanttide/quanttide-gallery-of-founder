# 资产维护

维护一个资产仓，不是把文件看好，是让一类内容在时间里一直可用：新的进得来，旧的退得出去，接手的人知道从哪看。

## 维护的三件事

- 边界：这条内容还属不属于这一类。
- 入口：别人能不能在索引里找到它。
- 时间线：改了什么，什么时候发布，旧版本还能不能追。

## 一、目录

内容只放在这一类约定的路径里。同一份内容不跨类复制——两处各存一份，迟早各自过时。

## 二、入口

新增内容同步进 README 或 index.md。入口是给下一个人的第一条线索，不能留空。

## 三、变更记录

CHANGELOG 按新增、变更与移除分开记。未发布的改动攒在 Unreleased，发布时定版成一段。

## 四、版本

版本用 semver。标签与 CHANGELOG 的版本段同名；已发布的段不回改，改了就要另发一个版本。

## 五、发布

先推资产仓，再回主仓更新子模块指针。顺序反了，指针会指向远端还不存在的提交。指针提交写清版本号。

## 六、提交

提交信息用 Conventional Commits；一次迁移在源侧与目标侧各自提交，不混成一个。

## 七、迁移

归档只移动文件，不改内容；移交按目标侧的体例重写。判断标准是内容过时还是换了读者，不是文件好不好看。

## 八、闸门

提交前跑语言、文档与表达检查。被拦下的旧文本不顺手改写——要么按规则改，要么留给术语治理，不在迁移里夹带。

## 九、淘汰

过时内容先移到归档，不就地删除。归档留一份可追溯的底；删除不可逆，归档不是。

## 怎么看出维护断了

- 索引里找不到最近的内容：入口断了一环。
- 标签与 CHANGELOG 对不上：版本线断了。
- 同一条内容在两个仓里各有一份：边界失守。
- 主仓指针停在旧提交：发布只做了一半。

## 边界

这些规则管资产仓怎么长期活着，不管内容怎么写。写法看对应资产的体例；一条内容该去哪，看归位规则。
