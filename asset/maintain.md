# 资产维护

维护资产，是让内容按同一套结构在三种位置之间走：context 是入口，长期记忆是常驻，archive 是出口。三种结构见 [relation.md](./relation.md)。

## 三步

1. **context 内整理与校验**：内容放成「领域 / 资产」，领域和资产都能认出来，才算通过。
2. **按规则移动**：前两段交换，`context/<领域>/<资产>/<余下>` → `<资产仓>/<领域>/<余下>`。
3. **目标仓二次整理**：按目标仓的体例与入口重新组织。

顺序不能变：先整理再移动，先移动再进目标仓整理。

## 通过的条件

- 前两段能认出领域与资产；资产在前、领域在后，也会被整理成领域在前。
- 目标位置还没有同名文件；已有则不覆盖。
- 目标仓顶层是领域，不是资产名；顶层出现资产名，说明二次整理还没做。

## 边界

- 只维护结构与位置，不改写正文。
- 归档与 context 同构：`archive/<领域>/<资产>/<余下>`，只换位置，不换顺序。
- 二十种资产：context 一种、长期记忆十八类、archive 一种。

## 不做的

- 不在移动时改体例；体例归目标仓的二次整理。
- 不判断内容属于哪个领域；领域来自 context 的一级文件夹。
- 不替人提交、推送或更新指针。
