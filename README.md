# quanttide-gallery-of-founder

量潮创始人案例集 — 精选判例与案例。

## 定位

案例集收判例：回答「遇到过什么、当时怎么处理」。先有案例、后有标准，案例从实践中积累，标准从判例中归纳。与同域资产的分工：

| 资产 | 承担 | 问题 |
|------|------|------|
| `data/context` | 驱动 | 现在带着什么上下文干活？ |
| 手册（`docs/handbook`） | 规范 | 具体怎样做？ |
| 案例集（本仓库） | 判例 | 遇到过什么、当时怎么处理的？ |

## 概述

本仓库用于收录量潮创始人的精选案例（判例库）。当前收录：

- [create/food.md](create/food.md)：媒体与图文——美食推荐图文的发布过程。
- [work/agent/index.md](work/agent/index.md)：智能体协作——职责分工、操作要求与已知限制。
- [work/agent/desktop-workflow.md](work/agent/desktop-workflow.md)：电脑端工作流——入口按职责分工与操作步骤。
- [work/agent/mobile-workflow.md](work/agent/mobile-workflow.md)：移动端工作流——手机派单与查收、电脑执行、官网 App 评审。
- [work/agent/hermes-workflow.md](work/agent/hermes-workflow.md)：后台实现任务派单——Hermes 转发、Pi 执行。
- [work/export-icloud-photo.md](work/export-icloud-photo.md)：媒体与素材——从 iCloud 相册导出照片与视频（工作流）。
- [work/continuous-process.md](work/continuous-process.md)：连续流程——先定义完整学员旅程，再分段迁移跨系统人工衔接。
- [code/](code/)：产物本身的踩坑清单（文件编辑、语言与测试写法、检索与数据）。
- [agent/discipline.md](agent/discipline.md)、[agent/pi.md](agent/pi.md)：协作纪律与 pi 运行时。
- [agent/intent-formalization.md](agent/intent-formalization.md)：意图形式化——先把意图写成规则与异常，再让 AI 和程序执行。
- [agent/verifiable-records.md](agent/verifiable-records.md)：可核对记录——重要状态变更留记录，AI 流程与交接靠校验兜底。
- [language/context.md](language/context.md)：语境错配——财务与计算机术语搬出本领域的词表、替代写法与判断界线。
- [asset/catalog.md](asset/catalog.md)：资产清单——二十种资产的名字、路径、角色与布局。
- [asset/maintain.md](asset/maintain.md)：资产维护——三步流程与通过条件。
- [asset/relation.md](asset/relation.md)：资产关系——context、18 类长期记忆与 archive 的搬迁。
- [meta/](meta/)：归位——先定去处再定范畴，落位卡点名哪些前提。
- [meta/axioms.md](meta/axioms.md)：公理清单九条；[meta/property.md](meta/property.md)：标准属性。
- [meta/model/index.md](meta/model/index.md)、[meta/relation.md](meta/relation.md)：标准模型与标准关系。
- [meta/home.md](meta/home.md)：标准去处；[domain/human-vs-org.md](domain/human-vs-org.md)：域界线——人力资源与组织管理，归到人还是归到组织。
- [org/rank.md](org/rank.md)：晋升通道——实训基地、联盟、公司三级，培养与选拔并用。
- [org/structure.md](org/structure.md)：组织结构——联盟下设实训基地和研究院，分级训练。
- [org/right.md](org/right.md)：职权——代表大会弱领导，项目里随阶段流动。
- [org/empowerment.md](org/empowerment.md)：逐步授权——先定底线，随可靠行为让权，决议约束双方。
- [org/points-ledger.md](org/points-ledger.md)：组织记录——成员积分制用可核对记录支持互助。
- [org/stage-leadership.md](org/stage-leadership.md)：阶段领导权——主导权贴近当前工作的专业判断。
- [org/resource-rules.md](org/resource-rules.md)：资源与规则——资源请求先讲清价值与成本，走制度提案。
- [human/training/product-operations.md](human/training/product-operations.md)：产品运营培养方案——从用户体验观察入手，用 Issue 与 PR 记录成长路径。
- [human/course-hiring-assessment.md](human/course-hiring-assessment.md)：课程招聘同源——课程与招聘共用任务和评分标准，门槛分设。
- [human/screening-at-scale.md](human/screening-at-scale.md)：筛选机制重设计——申请量超出容量时按实际规模重设计，考核转入真实任务。
- [human/crowdsourced-tasks.md](human/crowdsourced-tasks.md)：众包任务——真实需求拆成最小任务，连接课堂、招聘与实训。
- [human/promotion-stages.md](human/promotion-stages.md)：晋升阶段——用职级与候补层把成长路径拆成可观察阶段。
- [human/business-capability.md](human/business-capability.md)：岗位能力——商务岗位标准化后按获客与维护拆分，负责人接棒日常经营。

DevOps 阶段的清单已迁至 `quanttide-devops` 的案例集（[quanttide-gallery-of-devops](https://github.com/quanttide/quanttide-gallery-of-devops)），按阶段与主题落位，来源侧不留副本。
