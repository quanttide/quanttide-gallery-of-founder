# 用众包任务连接真实需求、训练与选拔

## 方案目标

将企业真实需求拆分为可由个人或小组完成的实训级任务，通过任务参与连接业务需求、人才训练和招聘选拔。

本方案参考具体众包平台与实训任务实践，不作为统一任务管理标准。

## 一、收集和筛选真实需求

**做什么：** 从企业项目中寻找适合开放给参与者的任务。

**怎么做：**
1. 收集当前项目中尚未解决的实际问题。
2. 判断任务是否可以独立拆分，不影响核心业务安全。
3. 排除涉及敏感信息、权限不足或必须由专业人员操作的事项。
4. 优先选择目标明确、工作量适中、结果能够检查的任务。
5. 记录任务来源和业务价值。

**通过条件：**
- 任务具有真实需求来源。
- 任务能够独立完成或明确划分协作范围。
- 交付结果可以被检查。

## 二、拆分实训级任务

**做什么：** 将较大的业务需求转化为新人可以尝试的具体任务。

**怎么做：**

每项任务至少包含：
1. 任务名称。
2. 背景与问题说明。
3. 任务目标。
4. 可使用的输入资料。
5. 具体工作范围。
6. 交付物格式。
7. 完成期限。
8. 验收方式。
9. 奖励说明（如适用）。

任务应尽量控制在个人或小组可以独立推进的规模。对于完整项目，不直接要求新人承担全部工作，而是拆成多个有明确交付边界的任务。

**通过条件：**
- 参与者能够理解任务。
- 不需要依赖大量未提供的内部信息。
- 任务能够在约定范围内完成。

## 三、发布与参与

**做什么：** 让参与者根据兴趣和能力选择任务。

**怎么做：**
1. 将审核通过的任务发布到众包任务入口。
2. 说明任务要求、参与条件和奖励规则。
3. 允许参与者根据自身情况选择任务。
4. 记录任务领取情况和负责人。
5. 在执行过程中提供必要的资料与沟通支持。
6. 遇到超出任务范围的问题时，及时联系任务负责人。

**通过条件：**
- 任务信息公开且完整。
- 参与者明确知道自己需要完成什么。
- 每项任务都有明确的责任人。

## 四、成果验收与激励

**做什么：** 根据任务要求验收成果，并对符合条件的贡献给予激励。

**怎么做：**
1. 任务负责人根据预先设定的验收标准检查交付物。
2. 将成果分为通过、需要修改和未通过。
3. 对需要修改的成果说明具体问题。
4. 对通过验收的成果记录贡献情况。
5. 根据任务事先公布的规则发放现金、代金券或其他约定奖励。
6. 保留奖励依据，避免出现事后随意改变规则的情况。

**通过条件：**
- 每项成果都有验收结论。
- 修改意见能够被理解和执行。
- 奖励与任务规则相对应。

## 五、将任务结果用于培养与选拔

**做什么：** 根据参与过程和成果判断后续培养方向。

**怎么做：**
1. 观察参与者是否能够主动选择任务。
2. 检查其问题理解、沟通、执行和交付能力。
3. 对持续表现良好者提供更复杂的任务。
4. 对暂时无法独立完成任务者提供指导。
5. 根据实际表现判断是否进入进一步培养或招聘环节。

**通过条件：**
- 人才评价有实际任务作为依据。
- 不只依据最终成果，也考虑参与过程。
- 后续培养方向与实际表现相匹配。

## 适用边界

本案例记录的众包平台及相关任务已经上线，并用于招聘、课堂和实训之间的衔接。但任务质量、奖励公平性和人才识别效果仍需持续验证。现金或代金券激励也应根据具体任务条件确定。本方案不构成统一的众包管理制度。
