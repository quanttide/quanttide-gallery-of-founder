# 产品运营培养方案

不教固定操作步骤，从用户体验观察入手培养运营：先会发现哪里不顺手、把问题说清楚，再逐步承担完整责任。每个团队的日常运营流程不同，固定步骤难以迁移，能迁移的是发现、描述、验证问题的能力。

## 成长路径

以普通成员身份使用产品 → 发现不顺手的地方并清楚表达 → 通过 Issue 提交问题与实测记录、通过 PR 提交改进建议 → 被委派承担运营工作 → 参与机制维护 → 与产品经理、架构师一起判断如何改进产品。

## 训练内容

- 观察：从真实使用里发现哪里不顺手。
- 描述：把问题说清楚，附上实测记录，落进 Issue。
- 验证：改进建议以 PR 提交，实际改进以合入验收。

## 载体

成长路径写在 Issue 与 PR 的参与里：提过什么问题、合过什么改进，就是培养记录。载体是组织机制，归的是培训职能。

## 边界

这是一条从实践中走出的具体路径，成员确实从群成员成长为运营并参与机制维护。它是实例，不是适合所有人的统一晋升标准。
