# DevOps

## 定位

研发流程的自动化与形式化：让规划、编码、构建、测试、发布、部署、运维、监控八阶段里的每一步都能被工具自动、可重复、可审计地完成。本目录按阶段归档，每条写「现象 → 做法」，不写论证。

## 分类标准

先归阶段，再看性质。

归阶段：这条坑挡住的是哪一步，就落在哪一站。看性质：只收用来让流程自动、形式化的知识；判断产物本身对错的，归 [代码](../code/index.md)。同一做法在多个阶段都成立（命令行语法、外部服务的通用调用），归 [tooling.md](./tooling.md)。

DevOps 不产出业务价值，只产出确定性。所以这里的条目大多不解释业务，只解释工具在什么条件下会不按预期工作。

## 关于空阶段

规划、发布、监控三站暂无条目。语料来自失败记录，失败集中在版本控制、构建与外部工具链；规划阶段的问题多是判断，监控阶段的问题多以指标形式存在，两者都没有沉淀成「现象 → 做法」。这里留空，不硬凑。
