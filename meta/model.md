# 标准模型

模型不是某一个类，是反复出现的形状：同一个东西在每个领域各出现一次，长相一样。五样都还没对过，先按怀疑算。每样写三段：定义、约束、出现。

## 契约（怀疑）

定义：一个领域全部规则与阈值的集合，写成一份 `default-contract.toml`，运行时由一个同名类整份读入内存，代码里不留规则。

约束：一个领域一份，不共用；缺了就停手，不内置兜底。查找顺序固定：先 `--rules`，再环境变量，再从当前目录往上找到源码树，最后退到用户级目录。

出现：code、language、docs、write、think、meta、agent 七处；asset 不另起一份，读 meta 的。

## 单元（怀疑）

定义：契约里能单独被引用、被检查的最小一条，带机器名与人读称呼。

约束：机器名在同类里不重复；字段按 [property.md](./property.md) 写；加一类东西只往契约里加单元，不改代码。

出现：格（`[[cell]]`）、领域（`[[domain]]`）、降格（`[[transition]]`）、分辨（`[[question]]`）、公理（`[[axiom]]`）、体裁、词。

## 结论（怀疑）

定义：一次检查交给人的结果，至少含结论、理由与位置。

约束：结论只从有限的几种里取——过、没过、待定、不收；理由要指到具体规则或具体位置，不写空话；退出码 0 表示过，非 0 表示没过或待定。

出现：meta 的落位卡（place、move、reject、undecided）、docs 与 language 的命中清单、write 与 think 的审计意见。

## 命令（怀疑）

定义：一个领域对外的唯一入口，读自己的契约、跑检查，把结论摆成文本或 `--json`。

约束：读命令不改内容、不搬文件；写命令只写自己那一处（澄清记录、技能目录、钩子）；命令之间不互相改规则，组合只发生在报告层。

出现：code、language、docs、write、think、meta、asset、product、agent、git；`audit` 是组合，不是新领域。

## 技能（怀疑）

定义：写给执行者的操作说明，规定什么时候触发、按什么步骤做，只引用命令，不携带规则。

约束：一个触发场景一份；引用的命令名与 CLI 一致；规则改了只改契约，技能不动。

出现：`~/.agents/skills/` 下各领域的技能。

## 怎么用这套形状

新开一个领域，照这五样各写一份：契约、单元、结论、命令、技能。不发明第六种结构，也不把别的领域的字段借过来用。

模型的错法与正法，见 [axioms.md](./axioms.md) 的判例。
