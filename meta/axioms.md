# 公理清单

归位之前，这些前提不必再论证。它们不是规矩——规矩可以逐事商量；前提是已经吃过的亏，改它就得把那个亏重新吃一遍。

每条写两半：前提，和不认它的代价。前提能背下来，代价只在真吃过之后才记得住，所以后一半更要留住。

| id | 前提 | 代价 |
|---|---|---|
| `one-place` | 一份内容只有一个正确去处。 | 放错格的代价不是难看，是下一轮没人找得到它。 |
| `domain-before-cell` | 先定域，再定格，再过准入，最后给写法。 | 顺序换了，域错时格越准，搬得越远。 |
| `text-only` | 只看正文，不看它现在住在哪。 | 现在的位置可能是上一次判错留下的。 |
| `no-fit` | 一格都套不上就不收，留在日志里等它重复。 | 硬归进某一格，只会让那一格多一条没人再看的记录。 |
| `one-source` | 同一内容只在一处完整展开，其余留一句互链。 | 两处都写同一个事实，就是两个真源。 |
| `no-fallback` | 契约缺了就停手，不内置兜底。 | 静默回退会让人以为规则生效了。 |
| `target-then-source` | 迁移先写目标、再删源，源侧不留复制件。 | 窗口里不能两边都空；完成后也不能两边都有。 |
| `archive-vs-transfer` | 归档只移动不改写；移交必须改体例。 | 改错了形态，历史对不上，或者目标仓多一份不合体的文。 |
| `template-scope` | 模板只归 `docs/` 下的手册与规格；陈述型不设固定写法，日志可以有日期模板。 | 陈述型靠能否被推翻验收，固定章节会掩盖论证。 |

## 怎么认出它

- 一句话该放哪争起来时，先分清争的是前提还是某一格。前提不认，格子谈得再准也没有用。
- 想推翻一条，先说出它记的是哪次亏。说不出，就是在推翻自己没经历过的东西。
- 一条前提如果天天要拿出来引，它其实已经是一条规矩，该写成能当场核对的条件。

## 判例

### 给洞察定章节

现象：写一篇洞察，先立「背景与问题、判断、机制、边界、结论」五段，段段齐全，读起来整齐。

错法：把别人文章的结构当成体裁本身。模板越细，正文越像填表，作者想说的东西反而没处放。

正法：陈述型只给禁区——不排章节、不写空话；模板留给手册与规格，日志只固定日期。判断一篇洞察成不成立，看它的结论能不能被推翻，不看它有没有五段。

### 搬家时两边都留

现象：一篇内容移到目标仓，源文件没删，两边都能打开，其后两处各自接着改。

错法：抄一份过去就当搬完。此后每一处修改都要做两遍，漏一遍就多一个真源。

正法：先写目标、再删源，中间只允许一处短暂完整；收尾时两边只剩一处，源侧不留复制件。

### 规则缺了就猜

现象：规则文件没找到，工具拿内置默认值继续跑，报告看着正常。

错法：静默兜底。没人知道这一次规则其实没生效，后续所有结论都悬在空中。

正法：找不到就停手报错。宁可少跑一次，也不要跑出一份看起来对的报告。

## 九条合起来

去处由内容决定，不由它现在在哪、也不由谁方便决定。定了去处，只留一份正本，其余留一句互链；收不下的先不收，等它再来一次。搬的时候先立后拆，中途两边不能都空，也不能都有；过时的只移动，不合体的要改写。模板只给手册、规格和按日期归的日志，其余不排章节。
