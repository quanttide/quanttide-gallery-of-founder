# 契约

约定两方各自承担什么。契约回答的是关系问题：边界划在哪里，越过边界由谁负责。

## 本意

双方或多方达成的、具有法律约束力的协议，写明各自的权利、义务与违约后果。它强调对等协商与约束力：劳动合同、租房合同都是本意上的契约。

## 计算机实现

计算机中的契约是契约式设计，即 Design by Contract：一个组件对调用方作出承诺，同时要求调用方先满足条件。契约由三样东西构成：

- 前置条件：调用方必须保证，否则后果自负
- 后置条件：被调用方必须保证，前提是前置条件成立
- 约束：双方共同维护，贯穿调用前后

接口定义与 API schema 是这一思路的弱化版：只声明形状与类型，不声明行为承诺。两者常被混称，区别在于是否对行为负责。

## 核心区别

本意上的契约靠法律效力与信任兑现；计算机中的契约靠断言与接口兼容性兑现，本身不产生现实世界的法律效力。智能合约是把两者接起来的尝试——条款写成代码，违约交给执行环境自动处理。

这也划出了分界：机器里的契约只有执行后果，没有道德后果。

## 在系统中的位置

契约位于架构与交互层，粘合模块之间的协作。调用支付接口必须传合法凭证，接口则保证返回成功或失败——这条约定成立，双方才可各自独立演进。

契约一旦松动，上层规则与下层实现都会开始互相猜测，协作随之退化为默契。
