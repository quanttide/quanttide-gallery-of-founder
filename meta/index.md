# 归位

## 定位

一份内容该放哪：先定域，再定格，再过准入，最后给写法。这一节收归位时不再论证的前提——每条都压着一类反复出现的错，错的代价写在同一行里。

前提与规则分开。规则写在 `apps/qtfounder/src/cli/src/meta/default-contract.toml` 的 `[[cell]]`、`[[transition]]` 与 `[[question]]` 里，参与算分；前提不参与算分，只在落位卡上点名出处。改规则改契约，改前提要先说服人。

## 公理清单

| id | 前提 | 代价 |
|---|---|---|
| `one-place` | 一份内容只有一个正确去处。 | 放错格的代价不是难看，是下一轮没人找得到它。 |
| `domain-before-cell` | 先定域，再定格，再过准入，最后给写法。 | 顺序换了，域错时格越准，搬得越远。 |
| `text-only` | 只看正文，不看它现在住在哪。 | 现在的位置可能是上一次判错留下的。 |
| `no-fit` | 一格都套不上就不收，留在日志里等它重复。 | 硬归进某一格，只会让那一格多一条没人再看的记录。 |
| `one-source` | 同一内容只在一处完整展开，其余留一句互链。 | 两处都写同一个事实，就是两个真源。 |
| `no-fallback` | 契约缺了就停手，不内置兜底。 | 静默回退会让人以为规则生效了。 |
| `target-then-source` | 迁移先写目标、再删源，源侧不留复制件。 | 窗口里不能两边都空；完成后也不能两边都有。 |
| `archive-vs-transfer` | 归档只移动不改写；移交必须改体例。 | 改错了形态，历史对不上，或者目标仓多一份不合体的文。 |
| `template-scope` | 模板只归 `docs/` 下的手册与规格；陈述型不设固定写法，日志可以有日期模板。 | 陈述型靠能否被推翻验收，固定章节会掩盖论证。 |

## 卡上点哪几条

落位卡只点名这次真用到的，不摊全表：

- 每张卡：`domain-before-cell`
- 指了域：`text-only`、`archive-vs-transfer`
- 收了（落位或搬走）：`one-place`、`template-scope`
- 不收：`no-fit`

对不上时先看这一行，再决定改哪里：前提不成立改契约，前提成立而卡错，是规则或执行的问题。

## 怎么用

- 评审里直接写 id，不重述原话：「这里违反 `no-fallback`」比复述一段省字，也不会每次复述都变形。
- 判错先分层：前提错改 `[[axiom]]`，相邻格分不开改 `[[question]]`，执行错改人、改提示词。三层混着改，本体就一点点漂走。
- 一条前提如果天天被引用，说明它其实该是一条规则，下沉到 `[[transition]]` 或代码检查。

## 来源

正本是契约里的 `[[axiom]]`，本页是给人看的镜像，改契约时同步；要看当前装的那份，跑 `qtfounder meta axiom`，只看一条加 id，如 `qtfounder meta axiom no-fallback`。契约里 id 重复、陈述为空、代价为空，读契约时就报错。
