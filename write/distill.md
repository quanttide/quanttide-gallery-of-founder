# 提炼

CODE 循环的 D 步骤。D 不删内容，把已有的内容重新打包成能读的样子。

案例：`docs/handbook/work/roadmap-maintenance.md` 按 `docs/handbook/docs/format.md` 重排的一遍。原文五节，内容都成立，问题全在格式。

## 章节带序号

现象：标题写成「一、核心认知：第一版必然冗余」「### Pass 1 · 生成」，序号和标题挤在一行，中英文标记混着用。

问题：读者要跳过序号才看到标题说的是什么；增删章节时序号还得跟着改一遍，改一次错一次。

做法：只留标题本身，「核心认知：第一版必然冗余」「第一遍：生成」。

## 表格装并列定义

现象：三个自检摊成三列表格，自检、要求、防的是什么各占一列。

问题：一列只装得下短语，一句完整的话被拆成三格，读者得把格子拼回来才知道在讲什么。三条之间是并列关系，不是需要横向对比的数据。

做法：拆成三段，每段按「是什么，防的是什么」写成完整句子。

## 连续加粗

现象：一段里连着四处加粗，普通名词和整句话都在加粗。

问题：加粗的句子和周围同一音量，看着哪句都重要，等于哪句都不突出。

做法：全部去掉，重点交给段落顺序。

## 符号替读者做判断

现象：措辞对比用勾叉符号标哪句对哪句错，引号一处英文双引号、一处直角引号。

问题：符号先于内容表态，读者还得回头对一遍原文说的是什么；同一篇里两套引号并存，读者会以为标记有含义。

做法：去掉勾叉，改成完整句子说清差别；引号统一成直角引号。

## 判断

改完的验收标准是能当场指出来，不是看着顺眼。每一条改动都指向读者的某一次停顿：这句话要不要拼、这个加粗想强调什么、这个符号在说什么。指不出来，就是只换了外观。

反例是按比例删字。表格压成短词、段落砍成零碎短句，行数少了，句子也不成形了。另一种反例是加粗换成斜体、表格换成列表，噪音还在，只是换了衣服。
