# 提炼

CODE 循环的 D 步骤：不删内容，重新打包。

## 案例

`docs/handbook/work/roadmap-maintenance.md` 的一遍改写。原文五节，内容都成立，读起来费劲：章节带序号，三个自检摊成三列表格，四处连续加粗，引号中英混用，措辞对比用勾叉符号标对错。

## 现象

原文难读，不是因为话难懂，是因为格式抢在内容前面下判断。

表格每格只装得下短语，一句完整的话被拆成三格，读者得把格子拼回来才知道在讲什么。四处连续加粗，看着哪句都重要，等于哪句都不突出。

## 做法

按同目录 `ai-assisted-writing.md` 的体例重排。去章节序号，三个自检拆成三段完整句子，每条写成「是什么，防的是什么」；去掉全部加粗和勾叉符号；引号统一成直角引号；破折号堆叠改成断句。原来那几句判断原样留着，动的全是包装。

## 判断

D 的验收不在变短，在内容一条没少、读者不用再在格式里找重点。判断办法是反向读一遍：这一层包装去掉，读者会不会少知道一件事？不会就去掉。

反例是按比例删字。表格压成短词、段落砍成零碎短句，行数少了，句子也不成形了。另一种反例是只改外观不改结构，加粗换成斜体、表格换成列表，噪音还在，只是换了衣服。
