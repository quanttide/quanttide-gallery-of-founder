# 提炼

CODE 循环的 D 步骤。它常被当成「删字数」，实际动作是先定留下的标准，再按标准删。

## 案例

一段口述落成一篇手册，见 `docs/handbook/write/ai-assisted-writing.md`：我用网页版大模型润色智能体写的文档，标出人类确认过的，AI 写的默认不可信。

## 现象

初稿按口述铺开成五节，每节都成立，但每节的后半段都在解释本节的前半段。「两条都与这一次写得好不好无关」「润色改的是表达」这类句子，读第一条默认就推得出来。

验收标准的第一版是四条可检查的规则：frontmatter 由人工改成 `confirmed`、每段能指出事实出处、润色没带进新说法、全文通读一遍。四条都能执行，但没有一条回答「这篇能不能给人看」。

## 做法

先换标准。验收改成以人能不能读为准：脱离对话记录能读懂、读完能复述、句子成形、完整通过一遍。标准一换，前面几节解释性的段落就没有位置，删起来不用犹豫。

再按同一条线删到底：删了这句，读者会不会少知道一件事？不会就删。落定的是两条默认、四步流程、四条验收，每条都删不动，删了做法就变模糊。

## 判断

提炼到位的标志是删不动，不是删得短。同一篇压到三节或一节，前者骨架还在，后者只剩结论，别人照着做不出来。

反例是把「完整」当目标，补背景、补定义、补注意事项。补进来的多是读者已经知道或查得到的，压回去等于没提炼。
