# 提炼

CODE 循环的 D 步骤：不删内容，重新打包。

## 案例

`docs/handbook/work/roadmap-maintenance.md` 的一遍改写。原文五节，内容都成立，读起来费劲：章节带序号，三个自检摊成三列表格，四处连续加粗，引号中英混用，措辞对比用勾叉符号标对错。

## 现象

原文不好读，问题出在排版，不在内容。表格每格只装得下短语，一句完整的话被拆成三格，读者得把格子拼回来才知道在讲什么。四处连续加粗，看着哪句都重要，等于哪句都不突出。勾叉符号替读者判了对错，读者反而要停下来对一遍原文说的是什么。

## 做法

按 `docs/handbook/docs/format.md` 的格式章程重排：去章节序号，三个自检拆成三段完整句子，每条写成「是什么，防的是什么」；去掉全部加粗和勾叉符号；引号统一成直角引号；破折号堆叠改成断句。

## 判断

D 做完看两处，字数不算数。

内容上看次要信息清没清掉。主判断以外的解释、举例、重复强调，读的人得先绕过去才看得到结论；逐句问这是主判断还是陪衬的，陪衬的删掉或并进主句。

格式上看 `docs/handbook/docs/format.md` 过不过。章程里每条都能当场对照，没有「差不多」这一档；有一条没照做，这一遍就还没炼完。

反例是按比例删字。表格压成短词、段落砍成零碎短句，行数少了，句子也不成形了。另一种反例是只改外观不改结构，加粗换成斜体、表格换成列表，噪音还在，只是换了衣服。
