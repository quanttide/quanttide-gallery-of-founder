# 命名对齐

本案例记录一条操作流程：当发现文件系统的命名与分类没有准确表达概念时，把它对齐概念。一次对齐的输入是一处用错的名字，出口是同名同义、跨仓库一致；过程交付四件事——确定概念与用词、判定文件归属、改名、更新引用并逐层提交。

## 情境

组织第二大脑的 `tutorial/`、`handbook/`、`essay/` 三个文档仓库里，各有一份 `role/title.md`，讲的都是「职位」：手册给职位下定义，随笔讲模块化职位，教程以钱弘俶的官职为样本解读职位。同一套组织档案的另一处 `data/profile/orgs/*/structure/title.md`，记的是「职务」。

同一个文件名 `title.md`，在一处指职位，在另一处指职务。查证英文：职位是 position，职务是 title；title 的本义正是头衔、职务，属于「职务」一侧。名字与概念对不上，是要修的缺口。组织自身的规范也已把二者分开：`quanttide-human` 的规格目录用 `organizations/positions/position.md` 讲职位。

## 角色分工

- 概念所有者：判定概念及其边界，选定用词；
- 命名执行者：枚举同名文件、按概念归类、改名、更新引用、逐层提交；
- 仓库维护者：确认改名不破坏本仓库的引用与构建。

小团队里三者常由一人兼任。

## 流程

1. 定概念与用词：说清职位（position）与职务（title）的边界，选定英文名；
2. 归名：全仓搜索 `title.md`，逐一判断每个文件承载的是职位还是职务——`role/title.md` 归职位，`structure/title.md` 归职务；
3. 改名：把三处 `git mv role/title.md role/position.md`，职务的 `structure/title.md` 不动；
4. 更新引用：改各仓库的 `README.md`、`index.md`、`myst.yml` 目录项与正文相对链接；
5. 提交：三处改名分属不同仓库，各自提交推送，主仓库逐层更新指针。

判别与改名的顺序不能反：先归类、后改名，才不会把职务的记录误改成职位。

## 命名规则

- 概念先行：用词从概念里长出来，先说清概念，再定名字；
- 一词一概念：同一个词不承担两个概念，同名两义优先消除；
- 命名即分类：目录名与文件名是概念层级的投影，命名定了，分类也就定了；
- 跨仓库同构：同一概念在不同仓库用同一个名字，改名同改同步。

## 检查清单

- [ ] 概念与英文用词已确定，边界写清
- [ ] 全部同名文件已枚举、按概念归类
- [ ] 该改的已改名，不该动的不动
- [ ] 各仓库的目录项与相对链接已更新
- [ ] 各仓库分别提交推送，主仓库指针已更新
