# 按工作阶段分配领导权和责任
以下为可执行的机制条目，写明各阶段谁主导、决策范围与交接条件，以及分歧时的最终决策规则。  
条目一：常设会议采用弱领导  规则内容：代表大会作为常设机制，主席和秘书负责组织会议，代表在投票权上平等。  适用范围：组织层面的提案与决议，不覆盖具体项目内的阶段分工。  执行与调整权：会议由主席、秘书召集；表决结果由代表大会形成。  
条目二：需求梳理阶段由产品角色主导  谁主导：产品角色。  决策范围：需求边界、优先级、验收口径；技术选型不在本阶段定。  交接条件：需求清单与验收口径写成可核对的文档，技术角色确认可承接后，主导权转入下一阶段。  执行与调整权：主导人由项目在启动时会同代表大会确定；中途变更需重新交接并留记录。  
条目三：规格与技术实现阶段由技术角色主导  谁主导：技术角色。  决策范围：技术方案、实现顺序、规格细化；需求范围变更须回到条目二重新确认。  交接条件：实现完成并通过按条目二验收口径的检查，成果与待办清单移交下一环节。  执行与调整权：技术角色在本阶段范围内决策；超出范围的事项退回对应阶段。  
条目四：交接条件通用规则  规则内容：每次主导权转移都要有书面交接：当前结论、未决事项、下一阶段的负责人与决策范围。  适用范围：所有阶段之间的主导权转移。  执行与调整权：由交出方与接入方共同确认，留档备查；缺交接记录视为未交接。  
条目五：分工写入章程与授权条款  规则内容：把可重复的分工经验写成章程和授权条款，同时保留按任务调整的余地。  适用范围：多次出现、结构稳定的阶段分工。  执行与调整权：由代表大会形成条款；单个项目需要偏离条款时，在项目启动时说明并留记录。  
条目六：角色轮换  规则内容：角色如何轮换，仍需持续明确。  适用范围：跨项目、跨阶段的人员安排。  执行与调整权：尚未确定；本文不预设轮换规则，留待后续章程或授权条款补充。  
条目七：分歧时的最终决策  规则内容：出现分歧时谁最终决策，仍需持续明确。  适用范围：阶段之间、角色之间无法协商一致的事项。  执行与调整权：尚未确定；本文不指定最终决策人。在书面规则形成前，分歧应记录为待决议事项，提交代表大会，而不是由某一方直接拍板。  
边界  这是具体实例，不作为统一标准。  提案原文记录内部讨论中出现了代表大会设计、实际角色分工和将分工写入规则的讨论；角色如何轮换、出现分歧时谁最终决策仍需要持续明确，本方案照实写为待明确，不代为设定规则。  原始讨论上下文、实践状态与结果表述仍待核对；如有后续数据或制度版本，可补充后再作为成
