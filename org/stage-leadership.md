# 按工作阶段分配领导权和责任

## 机制目标

根据项目当前所处的工作阶段和所需专业能力，动态确定项目主导者，使决策责任尽可能交给最了解当前问题的角色。

本机制参考实训基地代表大会及项目专业分工的具体实践。

## 一、明确组织层与项目层的职责

**规则内容：**

组织治理和具体项目执行分开管理。

**怎么做：**
1. 组织代表大会负责讨论组织公共事务、形成组织决议。
2. 主席、秘书等角色负责组织会议、整理议题和记录决议。
3. 具体项目由参与项目的成员根据工作阶段承担主导责任。
4. 组织层不代替项目负责人处理所有专业问题。
5. 项目负责人也不能超越授权范围替组织作出公共决策。

**通过条件：**
组织事务与项目事务的责任边界清晰。

## 二、按项目阶段确定主导角色

**规则内容：**

项目领导权随工作阶段变化，不默认由固定职位从头负责到尾。

**怎么做：**

| 工作阶段 | 可参考的主导角色 | 主要职责 |
|---|---|---|
| 需求发现与问题定义 | 产品角色 | 识别需求、梳理问题 |
| 方案与规格设计 | 产品与技术协作 | 明确功能、范围和实现要求 |
| 技术实现 | 技术角色 | 技术方案、开发与实现 |
| 测试与验收 | 对应专业负责人 | 检查成果是否满足要求 |
| 后续运营与维护 | 运营或维护负责人 | 跟踪使用情况和持续改进 |

以上分工根据具体项目调整，不代表固定组织架构。

**通过条件：**
每个阶段都有明确主导者，参与者知道由谁组织工作和承担阶段责任。

## 三、明确交接条件

**做什么：** 防止项目阶段变化时出现责任空缺。

**怎么做：**
1. 当前负责人整理已完成工作。
2. 说明当前问题、未完成事项和风险。
3. 提交相关文档、设计或工作记录。
4. 由下一阶段负责人确认接收。
5. 明确新的决策范围和责任边界。

**通过条件：**
下一阶段负责人能够依据已有资料继续推进，不需要重新摸索全部工作。

## 四、明确决策范围

**规则内容：**

项目负责人只在已经授权的专业范围和工作阶段内作出决定。

**怎么做：**
1. 开始阶段明确负责人可以决定的事项。
2. 对涉及项目范围、资源投入和重大方向变化的事项，提交相应决策主体讨论。
3. 对涉及其他专业领域的问题，邀请对应角色参与判断。
4. 对重要决策记录理由和结果。

**通过条件：**
项目成员能够判断某项问题由谁决定，以及何时需要升级讨论。

## 五、分歧处理

出现专业意见分歧时：
1. 首先明确分歧属于当前阶段的专业问题，还是涉及整体目标的组织问题。
2. 专业问题由当前阶段主导者组织讨论。
3. 涉及跨阶段、跨部门或组织公共利益的事项，提交相应组织程序处理。
4. 记录不同意见、讨论依据和最终决定。
5. 对仍无法明确的事项，标记为待确认，不假设某一角色天然拥有最终决定权。

## 适用边界

本案例中已经出现代表大会设计、专业分工和领导权随工作阶段流动的讨论。角色轮换规则以及出现分歧时的最终决策机制仍待明确。因此，本条仅整理阶段性分工和交接方法，不将尚未确定的决策规则写成既定制度。
